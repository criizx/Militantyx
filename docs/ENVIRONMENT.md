# Среда выполнения

## Целевая среда

- операционная система: Ubuntu 24.04 LTS;
- архитектура испытательного стенда: x86_64;
- компилятор: GCC или Clang с поддержкой C++23;
- система сборки: CMake 3.25 или новее;
- тестирование: Catch2 3 и CTest;
- контейнеризация: Docker и Docker Compose;
- live-захват: Linux AF_PACKET, PACKET_MMAP и TPACKET_V3;
- хранилище: ClickHouse;
- основные C++-зависимости: Drogon и spdlog.

Это требования к целевой реализации. Существующие Dockerfile и Compose
пока являются каркасом: core запускает logger smoke test, ML и dashboard
как сервисы ещё не добавлены. Зависимости Dockerfile необходимо согласовать
с Catch2, который уже требуется при конфигурации тестов CMake.

## Среда разработки

Разработка ведётся на macOS. Чтение PCAP, переносимые парсеры и модульные
тесты могут выполняться нативно; Linux-совместимость проверяется в контейнере.
Архитектура контейнера на Apple Silicon может отличаться от x86_64:
результаты такой сборки не подменяют измерения целевого стенда.

В Compose компоненты обращаются друг к другу по именам сервисов внутренней
сети. Loopback используется только для процессов одного хоста или контейнера.

## Live-захват и испытания

Для live-захвата процессу необходима capability CAP_NET_RAW и видимость
нужного интерфейса. Docker Desktop на macOS не предоставляет прямой доступ
к физическому сетевому интерфейсу хоста, поэтому live-испытания проводятся
на Linux-хосте или Linux-ВМ с подходящей сетевой конфигурацией.

Сенсор получает копию трафика через зеркальный порт, TAP или подготовленный
виртуальный интерфейс. Требуется проверить видимость обоих направлений;
наблюдение одного шлюза не гарантирует видимость внутренних соединений.

В отчёте фиксируются CPU, RAM, NIC, ОС, компилятор, конфигурация захвата,
размеры пакетов, число потоков и версии наборов данных. Потери источника,
обработки, ML-заданий и экспорта в БД измеряются отдельно.
