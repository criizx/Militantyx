# План реализации

План реализации графового анализа сетевых взаимодействий.
Отмечены только выполненные задачи.

## Основа проекта

- [x] C++23, CMake, адаптер spdlog и smoke-тест.
- [x] Подключение Catch2 3 и CTest.
- [x] Скрипты форматирования, сборки, clang-tidy и Git-хуки.
- [x] Workflow GitHub Actions для существующего C++-проекта.
- [ ] Заменить PCAP-тест `REQUIRE(true)` проверками реального чтения.

Удалённый запуск workflow ещё не проверен.

## Этап 1. Данные и постановка эксперимента

- [ ] Проверить доступность и пригодность публичных PCAP и стендовых записей.
- [ ] Зафиксировать легальный фон, сценарии и основания разметки.
- [ ] Составить манифест захватов и определить отложенные сценарии.
- [ ] Утвердить единицу решения, разделение train/validation/test и метрики.

Этап завершён, когда собраны данные для первого сравнения
и описано их разделение.
Данные готовятся одновременно с чтением PCAP.

## Этап 2. PCAP и потоки

- [ ] Реализовать чтение классического PCAP; проверить EOF и повреждения.
- [ ] Добавить разбор Ethernet/IPv4/TCP/UDP с проверкой границ.
- [ ] Реализовать двунаправленный ключ, тайм-ауты, счётчики и ревизии.
- [ ] Экспортировать записи потоков и статистику неполных наблюдений.

Этап завершён, когда потоки из тестовых захватов совпадают
с ожидаемыми записями.
[OFFLINE_SESSION.md](OFFLINE_SESSION.md) остаётся отдельным планом PCAP-модуля.

## Этап 3. Граф и признаки

- [ ] Зафиксировать вершины, рёбра, направление, окно и правила агрегации.
- [ ] Построить граф с привязкой к исходным flow_id.
- [ ] Реализовать потоковые и графовые признаки по версионируемой схеме.
- [ ] Проверить границы окон, долгоживущие потоки и повторяемость результата.

Этап завершён, когда повторная обработка PCAP даёт тот же граф
и таблицу признаков.

## Этап 4. Офлайн-детектор

- [ ] Создать Python-проект и единые преобразования для обучения и оценки.
- [ ] Обучить baseline на нормальном трафике, сохранить модель и конфигурацию.
- [ ] Выбрать порог на validation и оценить отложенные сценарии на test.
- [ ] Сохранить оценки, статусы ошибок и ссылки на окна и потоки.

Этап завершён, когда работает офлайн-прототип и получено первое сравнение.

## Этап 5. Исследование

- [ ] Сравнить потоковые, графовые и совместные признаки.
- [ ] Проверить ложные тревоги на новых легальных приложениях и C2-сценарий.
- [ ] Провести отдельный эксперимент с шумом обучающих меток.
- [ ] Проверить чувствительность к задержкам и размерам пакетов.
- [ ] Измерить время обработки, память и задержку до решения.
- [ ] Сохранить команды, манифесты, таблицы и ограничения выводов.

Этап завершён, когда эксперименты можно повторить
и по результатам сделать вывод о гипотезе.

## Этап 6. Расширения после проверки метода

- [ ] При необходимости воспроизвести HyperVision и FlowPrint для сравнения.
- [ ] Рассмотреть RAPIER и NetMasquerade для дополнительных экспериментов.
- [ ] Добавить хранение в ClickHouse, API Drogon и интерфейс React.
- [ ] Реализовать live-захват Linux и асинхронный инференс.

Эти расширения не заменяют обязательное сравнение методов.
DoH/DoT, VPN, блокировка, QUIC и полный DPI не входят в обязательный объём.
