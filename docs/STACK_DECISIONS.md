# Технологический стек

Таблица описывает целевой стек; готовность компонентов отражена
в [плане задач](TASK_BREAKDOWN.md).

| Подсистема | Технологии |
|---|---|
| Разработка | macOS; офлайн-проверки нативно и в Linux-контейнере |
| Эксплуатация и нагрузочные испытания | Ubuntu 24.04 LTS, Linux-хост |
| Сенсор и backend | C++23, CMake |
| Live-захват | AF_PACKET, PACKET_MMAP, TPACKET_V3 |
| Офлайн-источник | Классический PCAP; поддерживаемые варианты фиксируются тестами |
| DPI | Собственные ограниченные парсеры TLS и выбранных протоколов |
| Правила и политика | C++: протокольные признаки, разрешения и маршрутизация |
| ML | Python, scikit-learn, Isolation Forest как базовая модель |
| Передача на инференс | Ограниченная очередь в C++, отдельный HTTP worker, пакетный JSON |
| Хранилище | ClickHouse, пакетная асинхронная запись |
| REST и WebSocket | Drogon |
| Frontend | React, TypeScript, Vite |
| Графики | Recharts или ECharts; выбор при реализации frontend |
| Запуск компонентов | Docker Compose |
| Журналирование | spdlog через единый C++-адаптер |
| Тестирование C++ | Catch2 и CTest |

## Обоснование

AF_PACKET/PACKET_MMAP используется для live-захвата на Linux. PCAP-источник
обеспечивает воспроизводимые тесты на macOS и Linux без доступа к сетевому
интерфейсу. Прикладной разбор имеет лимиты буфера и времени; базовые счётчики
потоков обновляются независимо от решения направить наблюдение в ML.

Isolation Forest оценивает числовые признаки потоков и временных окон.
Для разных схем наблюдений обучаются отдельные модели. Модель не определяет
тип атаки: категории и основания предупреждений формируются детекторами.
LLM в базовый стек не входит.

Python работает отдельным процессом. При запуске непосредственно на хосте
допустим loopback-адрес; в Compose используются имена сервисов внутренней сети,
а не localhost другого контейнера. Формат и версии признаков проверяются
на обеих сторонах.

Drogon обслуживает API и WebSocket; сетевые запросы к Python и ClickHouse
не выполняются в обработчике пакета. ClickHouse хранит метаданные, версии
снимков, результаты анализа и предупреждения. Для первого этапа достаточно
ограниченных очередей в памяти; отдельный брокер сообщений не требуется.
После аварии такие очереди не обеспечивают гарантированную доставку.

C++23 и асинхронная обработка сами по себе не доказывают высокую
производительность. Пропускная способность, потребление памяти, потери
и задержка подтверждаются испытаниями на фиксированном стенде.
