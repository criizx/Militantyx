# Архитектура системы

## Организация репозитория

Проект разрабатывается в виде монорепозитория. Исходный код C++-ядра,
ML-сервиса и веб-интерфейса размещается в едином репозитории в отдельных
подкаталогах `sources/core`, `sources/ml` и `sources/dashboard`. Общий
репозиторий обеспечивает согласованное изменение контрактов FlowRecord, REST
API и WebSocket-событий, а также единый запуск интеграционных проверок.

Каждый компонент сохраняет собственные зависимости и средства тестирования.
Корневые скрипты и CI выполняют проверки всех компонентов, присутствующих в
репозитории.

## Структурная схема

```text
PCAP-файл или сетевой интерфейс
                |
                v
Модуль захвата и разбора пакетов на C++
                |
                v
Модуль учёта сетевых потоков
                |
                v
Модуль машинного обучения на Python
                |
                v
ClickHouse <- Backend Drogon -> REST API и WebSocket
                                      |
                                      v
                         Веб-интерфейс React
```

## Обработка трафика

В офлайн-режиме источником данных является PCAP-файл. В режиме реального
времени применяется AF_PACKET с кольцевым буфером PACKET_MMAP версии
TPACKET_V3. Модуль разбора извлекает поля заголовков Ethernet, IPv4, TCP и UDP
и выполняет проверку корректности длины пакета и заголовков.

Сетевой поток задаётся набором из пяти параметров: исходного и целевого
IP-адресов, исходного и целевого портов, а также транспортного протокола.
Пакеты обратного направления включаются в ту же запись потока. TCP-поток
завершается по FIN/RST или по тайм-ауту неактивности; UDP-поток - по тайм-ауту.

Для завершённого потока рассчитываются время начала и окончания, длительность,
число пакетов и байтов по направлениям, средний размер пакета и сводные
TCP-флаги.

## Обнаружение аномалий

Для выявления отклонений применяется алгоритм Isolation Forest, обучаемый на
нормальном трафике. Вектор признаков включает длительность потока, число и
объём пакетов по направлениям, средний размер пакета, соотношение направлений,
транспортный протокол, категории портов и TCP-флаги.

Модуль машинного обучения возвращает оценку аномальности и метку аномального
потока. Взаимодействие C++ и Python компонентов выполняется по локальному HTTP
интерфейсу в асинхронном режиме.

## Хранение и визуализация

Завершённые потоки и предупреждения передаются через очередь и записываются в
ClickHouse пакетами. Состояние активных потоков хранится в памяти DPI-ядра.
Backend на Drogon предоставляет REST API для получения исторических данных и
WebSocket-канал для передачи новых потоков и предупреждений. Веб-интерфейс
отображает показатели нагрузки, временной график трафика, список потоков и
список аномалий.

## Среды выполнения

Разработка и обработка PCAP-файлов выполняются на macOS с использованием
Linux-контейнеров Docker Desktop. Режим захвата трафика и производительные
испытания выполняются на Linux-хосте или Linux-виртуальной машине.

## Перспективы развития

Перспективным направлением является реализация API реагирования на
предупреждения. API может формировать заявки на блокировку IP-адреса или порта.
Применение подтверждённых правил через nftables выполняется отдельным
привилегированным компонентом с ограниченным временем действия правил.
